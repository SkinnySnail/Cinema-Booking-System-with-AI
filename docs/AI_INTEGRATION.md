# Tích hợp AI vào hệ thống đặt vé

Bản triển khai bổ sung bốn nhóm chức năng AI vào PHP/React hiện có. Python chạy như dịch vụ nội bộ; PHP lấy dữ liệu thật từ MySQL, xác thực người dùng và trả kết quả cho React. Không cần thay đổi schema hoặc khóa API của nhà cung cấp AI.

## Chức năng và vị trí mã nguồn

Khách mới dùng độ phổ biến. Chỉ trả phim có suất tương lai, chưa ngừng chiếu, không loại C; áp dụng tuổi khi hồ sơ có ngày sinh. ## API

| API phía PHP | Dữ liệu đầu vào | Quyền / kết quả |
|---|---|---|
| `GET /api/ai/recommendations?limit=6&movie_id=1&cinema_id=2` | Các tham số tùy chọn, limit 1–12 | Quyền xem phim; ID người dùng lấy từ token. Danh sách phim, combo, `mode`, `ai_available`. |
| `POST /api/ai/chat` | `{"message":"Lịch chiếu ngày mai","context":{"movie_id":1,"cinema_id":2,"date":"2026-10-27"}}` | Quyền xem phim; trả `reply`, `links`, `context`, `ai_available`. Không tạo đơn hoặc thu tiền. |
| `POST /api/ai/reviews/sentiment` | `{"review_ids":[1,2]}` | Admin/Manager và `reviews.view_all`, giới hạn phạm vi rạp. PHP tự đọc nội dung đánh giá từ DB. |
| `POST /api/showtimes/auto-generate` | Các trường cũ, thêm `use_ai: true` | Admin/Manager và `showtimes.auto_generate`; Manager chỉ xếp lịch rạp phụ trách. `summary.ai` ghi `requested`, `used`, `mode`, `training_samples`. |

API Python `/recommendations`, `/chat`, `/sentiment`, `/forecast` chỉ nhận từ backend qua `X-AI-Key`. `/health` kiểm tra trạng thái tải mô hình. Không đưa khóa hoặc URL dịch vụ vào biến `VITE_*`. Dữ liệu chuyển sang Python gồm ID số, thuộc tính phim, văn bản đánh giá và số liệu tổng hợp; không chuyển tên, email, số điện thoại, mật khẩu hay thông tin thanh toán khách hàng.

## Chạy cục bộ trên Windows

Cần Python 3.11 hoặc 3.12, PHP có cURL, MySQL của dự án và Node cho frontend. Thực hiện tại thư mục gốc repo:

```powershell
python -m venv ai-service/.venv
ai-service/.venv/Scripts/python.exe -m pip install -r ai-service/requirements.txt
# Tạo khóa riêng cho phiên chạy. Không đưa khóa vào Git.
$env:AI_SERVICE_KEY = python -c "import secrets; print(secrets.token_hex(32))"
$env:AI_SERVICE_URL = 'http://127.0.0.1:8001'
$env:AI_ENABLED = 'true'
```

Trong terminal có cùng `AI_SERVICE_KEY`, chạy:

```powershell
Set-Location ai-service
.venv/Scripts/python.exe -m uvicorn app:app --host 127.0.0.1 --port 8001
```

Trong terminal backend, đặt **cùng giá trị khóa** và hai biến URL/ENABLED ở trên, sau đó chạy lệnh backend thường dùng:

```powershell
php -S localhost:8000 -t backend backend/index.php
```

Có thể lưu ba biến vào `backend/.env` riêng, được Git bỏ qua. Khi đó terminal Python vẫn cần `AI_SERVICE_KEY` trong môi trường. `backend/config/Env.php` ưu tiên biến môi trường đã có. Không sửa các khóa đang dùng của hệ thống. Frontend chạy như trước bằng `npm ci` rồi `npm run dev` trong `source-code/galaxy-cinema-hub-main`.

## Chạy Docker cục bộ (tùy chọn)

`docker-compose.ai.yml` là lớp cấu hình bổ sung cho `docker.yml`, không thay thế cấu hình triển khai hiện có. AI không công khai cổng ra host. Khóa phải được tạo riêng trước khi chạy:

```powershell
$env:AI_SERVICE_KEY = python -c "import secrets; print(secrets.token_hex(32))"
docker compose -f docker.yml -f docker-compose.ai.yml --profile ai up --build db ai app frontend
```

Không có khóa, Compose dừng với thông báo cấu hình thiếu. Cấu hình production chưa được thay đổi. Khi đưa lên môi trường khác cần cấp khóa riêng qua hệ thống quản lý biến môi trường tương ứng.

## Hành vi khi thiếu dữ liệu hoặc mất kết nối

- Gợi ý: dùng phim đang có lịch chiếu, xếp theo độ phổ biến; trả `popular_fallback` và `ai_available=false`.
- Trợ lý: trả liên kết tra phim/lịch chiếu khi AI mất kết nối. Không tự đoán suất chiếu.
- Cảm xúc: báo chưa kết nối để người quản lý thử lại; không tự đưa nhãn giả.
- Sinh lịch: mất kết nối dùng thuật toán trọng số hiện có, ghi rõ trên bản xem trước. Dưới 20 suất lịch sử hoặc mục tiêu không biến thiên dùng `smoothed_prior`; UI báo dữ liệu còn ít. Đủ dữ liệu dùng `random_forest`.
- `AI_ENABLED=false` ở backend tắt gọi dịch vụ; không có khóa thì cầu nối từ chối gọi. Không có khóa mặc định công khai.

## Kiểm thử và giới hạn chất lượng

```powershell
Set-Location ai-service
.venv/Scripts/python.exe -m pytest -q
.venv/Scripts/python.exe evaluate.py
```

Các kiểm thử PHP–Python là tùy chọn: đặt `PHP_BIN` trỏ tới `php.exe`; PHP cần có cURL. Khi dùng PHP portable với `-n`, có thể đặt thêm `PHP_EXTENSION_DIR` trỏ tới thư mục `ext`. Bộ kiểm thử tự mở dịch vụ trên cổng localhost tạm, tạo khóa ngẫu nhiên và dừng tiến trình khi xong. Kiểm thử frontend: `npm test`; build: `npm run build`.

Mô hình cảm xúc là **baseline TF-IDF + Logistic Regression**, chưa phải PhoBERT. Tập huấn luyện hiện có 72 câu tự soạn (24 câu mỗi lớp), chưa đại diện cho đánh giá thật. Đánh giá chéo phân tầng 4 fold (seed 7), trong đó vectorizer chỉ fit trên phần train, cho accuracy **0,4583**, macro-F1 **0,4473**. Đây là bằng chứng chưa đủ chất lượng cho kiểm duyệt tự động. Điểm xác suất hiển thị không phải độ chính xác đã được kiểm chứng. Cần tập dữ liệu tiếng Việt độc lập, có quyền sử dụng, kiểm tra nhãn và đo lại trước khi vận hành.

Trợ lý dùng bộ phân loại ý định nhỏ và tra thực thể có quy tắc, chưa phải trợ lý LLM tổng quát; chưa hỗ trợ mọi cách diễn đạt, tiếng lóng, hoặc truy vấn địa lý “gần tôi” theo vị trí thực. Gợi ý hiện học từ lịch sử vé đã thanh toán và nội dung phim, chưa ghi nhận click/xem trang. Combo dùng lịch sử mua và độ phổ biến. Dự báo học lại trên snapshot khi yêu cầu; chưa có pipeline huấn luyện theo lịch hoặc kho mô hình. Không tuyên bố đạt các mục tiêu Precision/Recall/MAE/accuracy trong báo cáo khi chưa có tập đánh giá thật.

Chưa chạy luồng end-to-end với MySQL/Docker của dự án trong phiên triển khai này vì Docker daemon không hoạt động. Đã kiểm tra riêng mô hình, cầu nối PHP–Python, luồng giao diện và bản build frontend; cần kiểm tra lại với DB có dữ liệu thật trước khi triển khai.

Kết quả kiểm thử tại thời điểm bổ sung: **22 ca Python/PHP** và **7 ca frontend** qua; PHP syntax check qua cho các file thay đổi; Vite production build và lint các module AI mới qua trong bản sao dùng đúng `package-lock.json`; Compose overlay qua kiểm tra `config --quiet`. TypeScript toàn repo báo 29 lỗi, giống hệt bản gốc HEAD khi chạy cùng bộ thư viện, ở `TicketChecker.tsx`, `BookingSuccessPage.tsx`, `RegisterPage.tsx` và các service cinema/movie/showtime có sẵn; không phát sinh lỗi TypeScript mới do phần AI. Bản build vẫn cảnh báo kích thước bundle lớn.
